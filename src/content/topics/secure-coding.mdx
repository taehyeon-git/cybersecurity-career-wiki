# 안전한 코딩

## 정의와 범위 · 먼저 이해하기

입력·권한·오류·비밀정보를 코드에서 안전하게 다루는 개발 습관과 검토 방법. 이 문서의 주제는 여러 직무에서 함께 사용하는 지식이며, 특정 채용 직무 하나와 동일하지 않다.

## 왜 필요한가

같은 취약점이 반복되는 원인은 개발 단계의 설계·구현 선택에 있다. NIST SSDF 1.1은 안전한 개발 관행을 기존 개발 수명주기에 통합하도록 권고한다.

## 핵심 개념과 구성 요소

신뢰할 수 없는 입력, 매개변수화 쿼리, 출력 인코딩, 서버 측 권한 검사, 안전한 오류 처리, 비밀정보 보호를 구분한다. CWE는 약점 유형을 설명하는 공통 어휘다.

## 기본 작동 원리

입력의 형식과 범위를 검증하고 구조화된 API로 처리하며 결과가 출력되는 맥락에 맞게 인코딩한다. 실패할 때는 내부 정보를 노출하지 않으면서 운영자가 추적할 기록을 남긴다.

## 작은 예시

파일 이름을 사용자가 정한 문자열 그대로 경로에 붙이지 않고 서버가 생성한 식별자와 허용 확장자 정책을 사용한다. 정상·경계·오류 입력 테스트를 함께 제출한다.

## 위험과 한계

입력 검증 한 번으로 권한 오류나 논리 오류를 막을 수 없다. 언어와 프레임워크의 안전한 기본값도 버전과 구성에 따라 달라진다.

## 실제 보안 업무에서의 활용

AppSec은 코드 리뷰 기준과 개발자 가이드를 만들고 DevSecOps는 이를 자동 검사와 변경 리뷰 절차에 연결한다.

## 선행 학습과 관련 기술

선행 주제: **프로그래밍과 스크립팅, 웹과 HTTP 기초**. 관련 주제: **정적 애플리케이션 보안 테스트, 안전한 개발 수명주기, 웹 애플리케이션 보안**. 이 연결은 학습을 위한 제안이며, 회사마다 직무의 업무 범위는 달라질 수 있다.
