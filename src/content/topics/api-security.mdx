# API 보안

## 정의와 범위 · 먼저 이해하기

API의 객체·속성·기능 권한, 자원 사용, 버전 관리와 외부 API 신뢰를 다룬다. 이 문서의 주제는 여러 직무에서 함께 사용하는 지식이며, 특정 채용 직무 하나와 동일하지 않다.

## 왜 필요한가

API는 사용자 화면과 별개로 직접 호출될 수 있으므로 클라이언트가 제한해 준다는 가정이 위험하다. OWASP API Security Top 10:2023은 객체 수준 인가 실패를 첫 항목으로 다룬다.

## 핵심 개념과 구성 요소

객체 수준(BOLA), 속성 수준, 기능 수준 권한을 구별한다. 과도한 자원 사용, 미관리 엔드포인트, 외부 API 응답의 신뢰도 별도 위험이다.

## 기본 작동 원리

요청 토큰을 검증한 다음 대상 객체와 요청 동작을 서버 정책에 대조한다. 응답에서는 허용된 속성만 반환하고 비용이 큰 작업에는 한도와 관측 수단을 둔다.

## 작은 예시

주문 조회 API의 `/orders/42`를 다른 계정으로 요청하는 교육용 테스트를 만든다. 응답 코드뿐 아니라 타인의 항목이 하나도 노출되지 않는지 확인한다.

## 위험과 한계

인증 미들웨어가 있어도 객체 소유권 검사가 빠질 수 있다. 테스트 계정이 한 종류뿐이면 이런 오류를 찾기 어렵다.

## 실제 보안 업무에서의 활용

AppSec은 권한 행렬과 계약 테스트를 만들고 침투 테스터는 승인된 계정 조합으로 경계를 검증한다. 제품 보안은 폐기 API와 제3자 연동을 추적한다.

## 선행 학습과 관련 기술

선행 주제: **웹과 HTTP 기초, 인증과 인가**. 관련 주제: **웹 애플리케이션 보안, 위협 모델링, 보안 로그와 SIEM**. 이 연결은 학습을 위한 제안이며, 회사마다 직무의 업무 범위는 달라질 수 있다.
