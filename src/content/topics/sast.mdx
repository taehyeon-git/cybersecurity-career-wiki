# 정적 애플리케이션 보안 테스트

## 정의와 범위 · 먼저 이해하기

프로그램을 실행하지 않고 소스코드나 중간 표현을 분석해 의심스러운 약점을 찾는다. 이 문서의 주제는 여러 직무에서 함께 사용하는 지식이며, 특정 채용 직무 하나와 동일하지 않다.

## 왜 필요한가

개발자가 코드를 바꾸는 시점에 잠재 결함을 알려 주면 수정 맥락을 잃기 전에 처리할 수 있다. SAST는 실행 중 구성이나 실제 권한 상태를 모두 관찰하지는 못한다.

## 핵심 개념과 구성 요소

구문·데이터 흐름·호출 관계를 통해 위험한 입력이 민감한 처리 지점까지 도달하는지 분석한다. 규칙 결과는 약점 후보이며 실제 악용 가능성을 판단하려면 주변 코드와 통제를 확인한다.

## 기본 작동 원리

저장소 스캔 결과를 코드 위치와 CWE 유형에 매핑하고 수정 담당자에게 전달한다. CI에서는 새로 도입된 고위험 결과를 우선 검토하도록 기준선을 관리할 수 있다.

## 작은 예시

입력 문자열이 SQL 문장을 구성하는 경로가 표시되면 매개변수화 쿼리 사용 여부를 확인한다. 수정 뒤 같은 코드 경로를 검사하고 관련 단위 테스트를 실행한다.

## 위험과 한계

오탐은 실제 문제가 아닌 경고, 미탐은 존재하는 문제를 놓친 결과다. 규칙을 무조건 끄거나 모든 결과를 차단하면 검토 품질이 떨어진다.

## 실제 보안 업무에서의 활용

AppSec은 결과를 분류하고 수정 지침을 제공한다. DevSecOps는 파이프라인 실행·권한·예외 만료를 관리하며 제품 보안은 반복 패턴을 설계 문제로 환류한다.

## 선행 학습과 관련 기술

선행 주제: **프로그래밍과 스크립팅, 안전한 코딩**. 관련 주제: **동적 애플리케이션 보안 테스트, 소프트웨어 구성요소 분석, CI/CD 보안**. 이 연결은 학습을 위한 제안이며, 회사마다 직무의 업무 범위는 달라질 수 있다.
