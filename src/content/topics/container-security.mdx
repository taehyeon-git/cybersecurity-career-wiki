# 컨테이너 보안

## 정의와 범위 · 먼저 이해하기

이미지 생성·배포·실행의 각 단계에서 의존성, 권한, 격리와 비밀정보를 관리한다. 이 문서의 주제는 여러 직무에서 함께 사용하는 지식이며, 특정 채용 직무 하나와 동일하지 않다.

## 왜 필요한가

컨테이너는 배포 단위를 격리하지만 호스트 커널과 운영 환경을 공유한다. 작은 이미지와 제한된 런타임 권한이 공격면을 줄이는 데 도움이 된다.

## 핵심 개념과 구성 요소

기본 이미지, 계층, 사용자 ID, 파일시스템, 런타임 능력, 네트워크, 레지스트리와 서명·출처를 나누어 본다. 이미지 스캔은 실행 중 권한과 노출까지 설명하지 못한다.

## 기본 작동 원리

빌드 시 필요한 구성요소만 포함하고 비밀정보를 이미지에 넣지 않는다. 배포 시 비루트 실행, 필요한 권한만 허용, 이미지 출처 확인과 로그 수집을 적용한다.

## 작은 예시

로컬에서 같은 앱을 root와 비루트로 실행해 파일 접근 차이를 확인한다. 이후 읽기 전용 파일시스템을 적용하고 앱이 쓰기 위치를 명시하도록 수정한다.

## 위험과 한계

이미지 취약점 경고는 실제 사용 경로와 패치 가능성 검토가 필요하다. 컨테이너 격리만으로 호스트 또는 클러스터 전체의 보안이 완성되지는 않는다.

## 실제 보안 업무에서의 활용

DevSecOps는 이미지 빌드·검사를 자동화하고 클라우드 보안은 런타임 정책을 점검한다. 아키텍트는 서비스 분리와 데이터 접근을 설계한다.

## 선행 학습과 관련 기술

선행 주제: **리눅스와 시스템 기초, CI/CD 보안**. 관련 주제: **쿠버네티스 보안, 소프트웨어 구성요소 분석, 소프트웨어 자재 명세서**. 이 연결은 학습을 위한 제안이며, 회사마다 직무의 업무 범위는 달라질 수 있다.
