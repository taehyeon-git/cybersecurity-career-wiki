# 네트워크 기초

## 정의와 범위 · 먼저 이해하기

IP, DNS, TCP, TLS와 네트워크 경로를 이해해 통신 이상을 설명하는 기초 지식. 이 문서의 주제는 여러 직무에서 함께 사용하는 지식이며, 특정 채용 직무 하나와 동일하지 않다.

## 왜 필요한가

보안 이벤트는 대개 주소, 포트, 이름, 프로토콜과 시간으로 관측된다. 연결의 정상 경로를 모르면 단순 장애와 의심스러운 통신을 구분하기 어렵다.

## 핵심 개념과 구성 요소

IP 주소는 전달 대상을, DNS는 이름 조회를, TCP와 UDP는 서로 다른 전송 특성을 제공한다. TLS는 전송 구간의 인증과 암호화를 다루지만 애플리케이션의 권한 오류까지 해결하지 않는다.

## 기본 작동 원리

클라이언트가 DNS로 주소를 찾고, 경로를 거쳐 서비스 포트에 연결한 뒤 애플리케이션 요청을 보낸다. 네트워크 제어는 경계 장비뿐 아니라 호스트, 클라우드 보안 그룹, Kubernetes 정책에도 분산된다.

## 작은 예시

허가된 실습망에서 DNS 조회 결과와 TCP 연결, HTTPS 요청 로그의 시각을 맞춰 본다. DNS는 성공했지만 TCP가 실패한다면 이름 해석 이후의 경로 또는 정책을 조사한다.

## 위험과 한계

암호화된 트래픽의 내용은 패킷만으로 알 수 없고 NAT나 프록시 때문에 출발지 해석이 달라질 수 있다. 패킷 기록에는 개인정보가 들어갈 수 있어 취급 범위를 정해야 한다.

## 실제 보안 업무에서의 활용

네트워크 보안 엔지니어는 경로와 분리 정책을 검증하고 SOC 분석가는 연결 로그로 이상 행위를 조사한다. 침투 테스트에서도 승인된 범위의 노출 자산을 확인하는 기초가 된다.

## 선행 학습과 관련 기술

선행 주제: **사이버보안 기초**. 관련 주제: **웹과 HTTP 기초, 보안 로그와 SIEM, 클라우드 보안**. 이 연결은 학습을 위한 제안이며, 회사마다 직무의 업무 범위는 달라질 수 있다.
