# 웹과 HTTP 기초

## 정의와 범위 · 먼저 이해하기

브라우저, 서버, 요청·응답, 쿠키, 세션의 관계를 이해하는 웹 보안의 출발점. 이 문서의 주제는 여러 직무에서 함께 사용하는 지식이며, 특정 채용 직무 하나와 동일하지 않다.

## 왜 필요한가

웹 취약점은 대부분 요청에 담긴 입력과 서버의 처리·권한 판단 사이에서 발생한다. HTTP 구조를 알아야 재현 요청과 수정 검증을 정확히 작성할 수 있다.

## 핵심 개념과 구성 요소

메서드, URL, 헤더, 본문, 상태 코드가 요청·응답의 주요 요소다. 쿠키는 클라이언트 저장 수단이고 세션은 서버가 로그인 상태를 관리하는 방식이므로 둘을 같은 개념으로 보면 안 된다.

## 기본 작동 원리

브라우저가 요청을 보내면 서버가 인증 상태와 접근 권한을 확인하고 데이터를 처리해 응답한다. TLS는 통신을 보호하지만 서버가 잘못된 사용자의 객체를 반환하는 문제는 별개다.

## 작은 예시

자신의 실습 앱에서 로그인 후 쿠키가 포함된 요청과 로그아웃 후 요청을 비교한다. 요청의 사용자 ID만 바꿨을 때 다른 사용자의 데이터가 보이지 않아야 한다.

## 위험과 한계

상태 코드 200만으로 권한 검사가 맞는 것은 아니다. 캐시, 리다이렉트, 프록시가 실제 응답을 바꿀 수 있어 서버 기록과 함께 확인한다.

## 실제 보안 업무에서의 활용

AppSec은 요청 처리 흐름에서 취약점을 검토하고, 침투 테스터는 승인된 계정과 환경에서 재현한다. 제품 보안은 설계 단계에서 권한 경계를 정한다.

## 선행 학습과 관련 기술

선행 주제: **네트워크 기초**. 관련 주제: **인증과 인가, 웹 애플리케이션 보안, API 보안**. 이 연결은 학습을 위한 제안이며, 회사마다 직무의 업무 범위는 달라질 수 있다.
