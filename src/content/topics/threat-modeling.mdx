# 위협 모델링

## 정의와 범위 · 먼저 이해하기

시스템의 자산·신뢰 경계·공격 경로를 그려 설계 시점에 보안 질문을 찾는 활동. 이 문서의 주제는 여러 직무에서 함께 사용하는 지식이며, 특정 채용 직무 하나와 동일하지 않다.

## 왜 필요한가

배포 후 검사만으로 설계 자체의 위험을 모두 찾기 어렵다. 위협 모델링은 서비스가 무엇을 신뢰하고 실패 시 누가 영향을 받는지 먼저 드러낸다.

## 핵심 개념과 구성 요소

데이터 흐름도, 자산, 행위자, 신뢰 경계, 오용 사례, 완화책과 잔여 위험을 기록한다. 모델의 목적은 완벽한 공격 목록이 아니라 설계 결정을 더 잘 검토하는 것이다.

## 기본 작동 원리

서비스 경계와 데이터 이동을 그린 뒤 각 경계를 넘는 요청에 인증·인가·입력 검증·기록이 있는지 질문한다. 발견한 위험은 우선순위와 소유자를 정해 개발 작업으로 연결한다.

## 작은 예시

파일 업로드 서비스에서 브라우저, API, 객체 저장소, 검사 작업의 흐름을 그린다. 사용자가 제출한 파일이 다른 사용자의 다운로드 경로로 전달되는 지점을 검토한다.

## 위험과 한계

다이어그램이 오래되면 잘못된 확신을 준다. 제품 변경 때 갱신하고 실제 코드·운영 설정과 차이가 없는지 확인한다.

## 실제 보안 업무에서의 활용

제품 보안은 기능 설계 리뷰에, AppSec은 요구사항과 테스트 설계에, 아키텍트는 경계와 공통 통제 결정에 사용한다.

## 선행 학습과 관련 기술

선행 주제: **사이버보안 기초, 웹과 HTTP 기초**. 관련 주제: **안전한 개발 수명주기, API 보안, 제로 트러스트 아키텍처**. 이 연결은 학습을 위한 제안이며, 회사마다 직무의 업무 범위는 달라질 수 있다.
