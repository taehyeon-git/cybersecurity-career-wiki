# 웹 애플리케이션 보안

## 정의와 범위 · 먼저 이해하기

웹 서비스의 입력 처리, 세션, 접근 제어, 구성에서 생기는 위험을 체계적으로 다룬다. 이 문서의 주제는 여러 직무에서 함께 사용하는 지식이며, 특정 채용 직무 하나와 동일하지 않다.

## 왜 필요한가

웹은 외부 사용자와 내부 데이터가 만나는 지점이다. OWASP Top 10:2025는 인식 자료이며 모든 서비스에 동일한 우선순위를 강제하는 검사 목록은 아니다.

## 핵심 개념과 구성 요소

접근 제어, 보안 구성, 공급망, 암호 사용, 인젝션, 설계, 인증, 무결성, 로깅과 예외 처리가 주요 검토 축이다. 결함의 원인과 악용 조건을 구분한다.

## 기본 작동 원리

요청이 서버에 도착하면 입력을 구조적으로 파싱하고, 인증·인가를 평가한 뒤 데이터베이스나 외부 서비스에 전달한다. 각 단계에서 경계에 맞는 검증과 출력 처리가 필요하다.

## 작은 예시

교육용 앱에서 검색어에 특수문자가 들어와도 쿼리가 문자열 연결로 바뀌지 않도록 매개변수화 쿼리를 쓴다. 테스트는 정상 검색과 오류 입력을 모두 포함한다.

## 위험과 한계

자동 스캐너가 취약점의 업무 영향을 모두 알 수 없다. 재현 조건, 노출 범위, 원인 코드, 수정 후 회귀 시험을 함께 기록한다.

## 실제 보안 업무에서의 활용

침투 테스터는 승인된 시스템의 위험을 재현하고 AppSec은 개발자와 수정책을 설계한다. 제품 보안은 기능과 운영 수명주기 전체의 위험을 연결한다.

## 선행 학습과 관련 기술

선행 주제: **웹과 HTTP 기초, 인증과 인가**. 관련 주제: **API 보안, 안전한 코딩, 동적 애플리케이션 보안 테스트**. 이 연결은 학습을 위한 제안이며, 회사마다 직무의 업무 범위는 달라질 수 있다.
