# 쿠버네티스 보안

## 정의와 범위 · 먼저 이해하기

클러스터 API, 워크로드, RBAC, 네트워크 정책, 시크릿과 노드의 보안 경계를 다룬다. 이 문서의 주제는 여러 직무에서 함께 사용하는 지식이며, 특정 채용 직무 하나와 동일하지 않다.

## 왜 필요한가

컨테이너가 여러 노드에 배치되면 서비스 계정과 클러스터 API 권한이 곧 중요한 공격 경로가 된다. Kubernetes 공식 문서는 API 접근, RBAC, Pod 보안, 시크릿 관리 등을 별도로 다룬다.

## 핵심 개념과 구성 요소

공식 Kubernetes 보안 문서 v1.37(2026-10-09 확인)을 기준으로 Pod·Namespace·ServiceAccount·RBAC·NetworkPolicy·Secret의 역할을 구분한다. Namespace는 정리·정책 범위에 유용하지만 그 자체가 강한 격리 경계는 아니다.

## 기본 작동 원리

워크로드마다 서비스 계정을 지정하고 최소 RBAC를 부여한다. Pod Security Standards와 네트워크 정책을 적용한 뒤 정책 엔진과 네트워크 구현이 실제로 강제하는지 시험한다.

## 작은 예시

로컬 실습 클러스터에서 읽기 전용 서비스 계정이 Secret 목록을 조회하지 못하는지 확인한다. 기본 허용과 기본 거부 네트워크 정책의 연결 차이를 관찰한다.

## 위험과 한계

NetworkPolicy는 이를 구현하는 네트워크 플러그인과 정책 범위에 좌우된다. 시크릿은 API 객체이므로 접근 통제와 저장·전송 보호를 함께 검토해야 한다.

## 실제 보안 업무에서의 활용

클라우드 보안은 클러스터 기준 구성을 관리하고 DevSecOps는 배포 매니페스트 검사를 자동화한다. 아키텍트는 테넌트와 권한 경계를 정한다.

## 선행 학습과 관련 기술

선행 주제: **컨테이너 보안, 네트워크 기초, 신원 및 접근 관리**. 관련 주제: **클라우드 보안, 보안 로그와 SIEM, 제로 트러스트 아키텍처**. 이 연결은 학습을 위한 제안이며, 회사마다 직무의 업무 범위는 달라질 수 있다.
