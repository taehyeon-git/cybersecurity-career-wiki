## 왜 필요한가

사용자가 퇴사해도 계정이 남거나 서비스 계정에 지나친 권한이 있으면 네트워크 통제가 강해도 위험이 지속된다. IAM 엔지니어는 신원 확인과 자원별 권한 결정을 분리하고, 권한 부여·변경·회수의 전체 흐름을 운영한다. NIST Zero Trust는 네트워크 위치만으로 암묵적 신뢰를 주지 않는 자원 중심 접근을 설명한다.

## 실제 수행 업무

- **입력:** 인사·조직 변경 정보, 애플리케이션 접근 요구, 기존 역할·정책, 인증·감사 로그.
- **과정:** 사용자·서비스 신원을 구분하고 필요한 자원·행위만 허용하는 정책을 설계한다. 계정 생성·이동·퇴사 이벤트의 권한 변경을 자동화하고 실패·예외를 점검한다.
- **출력:** 승인 가능한 권한 행렬, 자동화 규칙, 접근 검토 증거, 남은 과도한 권한과 개선 계획.

## 가상 실무 시나리오

**가상 시나리오:** 팀 이동 후 개발자가 이전 운영 환경 접근권을 계속 갖고 있다. IAM 엔지니어는 권한 부여 경로를 추적하고 조직 변경 이벤트가 해당 서비스에 전달되지 않는 원인을 찾는다. 서비스 소유자와 역할별 최소 권한을 다시 정하고 권한 회수 자동화 및 예외 알림을 추가한다. 회수 후 필요한 업무 접근은 유지되는지도 확인한다.

## 기반 지식

인증은 신원을 확인하고 인가는 특정 행위를 허용하는 판단이라는 차이를 이해해야 한다. HTTP 세션·토큰 기초는 애플리케이션 연동 문제를 분석할 때 필요하다. 디렉터리·클라우드 IAM·서비스 계정 지식은 사람과 워크로드 접근을 나눠 설계하는 데 중요하다.

## 핵심 역량과 도구

ID 제공자는 인증과 계정 수명주기를, 정책 엔진은 자원 접근 결정을, 감사 로그는 실제 사용과 변경의 증거를 제공한다. 제품별 모델은 다르므로 정책은 허용·거부 테스트로 확인한다. [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)와 [NIST SP 800-207](https://csrc.nist.gov/pubs/sp/800/207/final)을 설계 참고로 사용한다.

## 신입 준비

‘IAM’, ‘계정·권한 관리’, ‘클라우드 접근관리’ 공고는 운영과 설계의 비율이 다르다. 역할별 접근 행렬과 퇴사·이동 이벤트 테스트를 보여주는 실습이 적합하다. 특정 공급자 자격증은 선택 가능한 학습 수단이며 공고별 필수 여부를 확인해야 한다.

## 학습 순서

1. 인증과 인가를 구분한다 — 실패 원인을 어느 단계인지 설명하면 완료.
2. 사용자·서비스 신원 수명주기를 그린다 — 생성·변경·회수 지점을 식별하면 완료.
3. 정책과 테스트를 작성한다 — 역할별 허용·거부 결과가 재현되면 완료.
4. 접근 검토를 자동화한다 — 미사용·과도 권한을 찾아 소유자에게 전달하면 완료.

## 실습 프로젝트

### 프로젝트 1: 역할별 접근 정책

- **목표·선수 지식·환경:** 관리자·일반 사용자·서비스의 권한을 분리한다. 인증 기초와 로컬 테스트 앱이 필요하다.
- **작업·검증:** 자원·행위 행렬을 만들고 기본 거부 정책과 역할별 테스트를 구현한다.
- **산출물·완료 기준·포트폴리오:** 정책, 테스트 결과, 예외 기록을 낸다. 모든 금지 조합이 거부되고 필수 업무는 유지되면 완료다.

### 프로젝트 2: 계정 회수 자동화

- **목표·선수 지식·환경:** 퇴사·팀 이동 이벤트 뒤 잔존 접근을 막는다. 이벤트 처리·로그 기초가 필요하다.
- **작업·검증:** 합성 인사 이벤트를 입력하고 권한·세션 변경과 실패 알림을 확인한다.
- **산출물·완료 기준·포트폴리오:** 수명주기 흐름도와 회수 증거를 제출한다. 실패 이벤트도 누락 없이 기록되면 완료다.

## 관련 자격증

Microsoft Entra 환경을 다룬다면 [Microsoft SC-300](https://learn.microsoft.com/en-us/learn/certifications/exams/sc-300/)의 신원 수명주기·인증·권한 범위를 참고할 수 있다. 공급자별 자격은 일반 IAM 원리와 다르므로 역할별 접근 테스트를 먼저 구현한다.

## 관련 직무 차이

클라우드 보안 엔지니어는 클라우드의 데이터·네트워크·워크로드 설정까지 다룬다. IAM 엔지니어는 여러 서비스에 걸친 신원과 권한 수명주기를 깊게 다룬다. GRC 분석가는 접근 통제의 정책·증거·위험을 평가할 수 있지만 구현을 직접 맡는 것은 조직에 따라 다르다.
