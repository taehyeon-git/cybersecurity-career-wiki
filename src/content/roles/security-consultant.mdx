## 왜 필요한가

조직은 보안 문제를 알고 있어도 어디에 먼저 투자하고 누가 실행해야 하는지 정하기 어려울 수 있다. 보안 컨설턴트는 명확한 의뢰 범위 안에서 증거를 수집하고 현재 상태와 목표의 차이를 정리해 의사결정을 돕는다. 컨설팅은 직무 기능이 넓은 실무 명칭이며 특정 NICE Work Role 하나와 동일하지 않다.

## 실제 수행 업무

- **입력:** 의뢰 목적, 조직·서비스 범위, 정책·아키텍처 문서, 인터뷰, 기술 점검 결과.
- **과정:** 평가 기준과 증거의 충분성을 합의한다. 기술·운영·인력 제약을 함께 보고 개선 대안의 효과와 실행 난도를 비교한다.
- **출력:** 근거별 현재 상태, 우선순위가 있는 권고, 담당 조직과 단계별 이행 계획, 미확인 항목.

## 가상 실무 시나리오

**가상 시나리오:** 중소 규모 조직이 클라우드 이전 전 보안 준비 상태를 점검받는다. 컨설턴트는 자산·데이터 분류, 계정 관리, 백업·로그 운영을 인터뷰와 설정 증거로 확인한다. NIST CSF 2.0의 결과 항목을 참조해 조직에 필요한 목표 상태를 제안하고, 클라우드 엔지니어가 실행할 수 있도록 우선순위와 책임자를 지정한다. 확인하지 못한 통제는 ‘부재’가 아니라 ‘증거 미확인’으로 남긴다.

## 업무에서 쓰는 역량과 도구

평가표는 기준과 발견을 연결하고, 증거 대장은 출처·날짜·소유자를 추적하며, 워크숍은 위험 수용과 실행 순서를 합의한다. [NIST CSF 2.0](https://www.nist.gov/cyberframework)은 결과 중심의 공통 언어로 사용할 수 있으나 단순 체크리스트 통과가 곧 안전을 의미하지 않는다.

## 신입 준비

‘보안 컨설팅’ 공고는 기술 진단, 클라우드 설계, 개인정보, GRC 등으로 세분화된다. 관심 분야를 명시하고 작은 조직의 가상 요구사항에 맞는 증거 기반 평가를 작성한다. 국내 법규·인증을 다루는 공고라면 현재 효력과 적용 범위를 별도로 검증해야 하며, 자격증을 역량 전체의 대체물로 여기지 않는다.

## 포트폴리오 작업 예시

### 프로젝트 1: 가상 조직 보안 상태 평가

- **목표·선수 지식·환경:** 제한된 자료로 개선 우선순위를 도출한다. 보안 기초와 합성 정책·설정 자료가 필요하다.
- **작업·검증:** 평가 질문을 작성하고 각 발견에 증거·반례·미확인 사항을 연결한다.
- **산출물·완료 기준·포트폴리오:** 현재·목표 상태표를 낸다. 주장마다 근거가 추적되면 완료다.

### 프로젝트 2: 개선 로드맵 워크숍

- **목표·선수 지식·환경:** 첫 프로젝트의 권고를 실행 순서로 바꾼다. 위험 우선순위 기초가 필요하다.
- **작업·검증:** 예산·인력 제약을 가정하고 대안별 효과·의존성·검증 지표를 비교한다.
- **산출물·완료 기준·포트폴리오:** 단계별 로드맵과 의사결정 기록을 제출한다. 실행 담당자가 다음 조치를 알 수 있으면 완료다.

## 과업이 시작될 때 확인하는 것

보안 컨설턴트는 고객의 요청을 곧바로 점검 목록으로 바꾸지 않는다. 계약과 범위서에서 무엇을 평가하고 어떤 결정을 지원할지, 고객이 제공할 증거와 인터뷰 대상은 누구인지 먼저 확인한다. 기술 진단, 관리체계 자문, 클라우드 설계 검토는 같은 '컨설팅' 이름 아래 있어도 수행 절차와 책임이 다르다. 중간에 새로운 위험이 드러나면 계약 범위 안에서 다룰지 별도 승인을 받을지 판단한다. 고객의 조직 제약을 이해하지 못한 개선안은 실행되지 않으므로 운영 담당자와 우선순위를 협의한다.

## 보고서와 고객 관계

결과 보고서에는 과업 목적, 대상·제외 범위, 사용한 기준, 증거의 수집 기간, 확인된 사실, 한계, 위험과 개선안의 담당 부서를 나눈다. 경영진 요약에는 의사결정이 필요한 항목을 먼저 적고 실행팀에게는 조치 순서와 검증 방법을 준다. 고객이 제공한 자료는 계약된 용도로만 사용하고 포트폴리오에는 익명화한 가상 사례를 사용한다. 권고가 법적 준수 여부를 확정하는 것처럼 보이지 않도록 적용 기준과 전문 검토가 필요한 부분을 명시한다.

## 국내 공고 확인 결과

안랩 공식 채용 목록에서 [보안 컨설팅 (경력)](https://ahnlab-cms.recruiter.co.kr/appsite/company/index) 공고명과 2026-10-02 게시, 10-11 마감이 확인됐다. 기업 원문 상세를 확보하지 못해 기술 진단과 관리체계 자문의 비중, 필수 기술, 구체 연차는 확인되지 않았다. 제목과 '경력' 표시만으로 모든 보안 컨설턴트가 같은 일을 한다고 해석하면 안 된다. 지원할 때에는 평가 대상, 고객 산업, 현장 업무, 보고서 책임을 공고와 면접에서 직접 확인해야 한다.

## 진입과 면접 증거

가상 고객에게서 '신규 서비스 출시 전 보안 상태를 평가해 달라'는 의뢰를 받았다고 가정하고 질문 목록, 범위서, 증거 요청, 발견 사항, 실행 가능한 개선 로드맵을 작성한다. 면접에서는 진단 결과를 나열하기보다 제약이 큰 고객에게 우선순위를 어떻게 합의했는지 설명한다. 보안 운영·개발·감사·GRC에서 각기 다른 과업으로 이동할 수 있지만, 자신의 전문 분야 밖의 결론은 전문가 검토가 필요하다고 인정하는 태도가 중요하다. 고객과 의견이 다를 때 사실과 권고를 분리해 기록한 사례도 좋은 증거다.

## 지원 전에 확인할 질문

- 계약의 주제가 기술 진단, 관리체계, 위험 자문 중 어디에 있는가?
- 고객 현장 인터뷰와 보고서 작성의 비중, 동시 수행 프로젝트 수는 얼마인가?
- 범위 밖 문제를 발견했을 때 추가 승인을 받는 절차가 있는가?
- 제안서 작성과 영업 지원도 수행하는지, 평가와 개선 자문에 집중하는가?

'보안 컨설팅'이라는 제목만으로 직무를 선택하면 실제 과업과 준비 역량이 어긋날 수 있다. 면접에서는 고객이 실행하기 어려운 권고를 했을 때 대안을 어떻게 조정했는지, 계약 범위와 증거의 한계를 어떻게 기록했는지를 제시한다.

## 근거와 확인 범위

역할 범위는 공식 역할 자료와 일반적인 고객 과업 구조를 참고했다. 국내 공고는 제목·기간에 한정된 사례이므로 상세 직무 요건의 근거로 삼지 않는다.
