## 왜 필요한가

서비스 간 통신을 무조건 열거나 닫으면 각각 노출과 장애가 발생한다. 네트워크 보안 엔지니어는 실제 업무 흐름에 필요한 경로만 허용하고 변경이 예상대로 작동하는지 검증한다. NIST Zero Trust Architecture는 네트워크 위치만으로 신뢰를 부여하지 않는 방향을 제시한다.

## 실제 수행 업무

- **입력:** 서비스 통신 요구, IP·DNS·포트 정보, 기존 정책, 변경 창과 장애 영향.
- **과정:** 데이터 흐름과 신뢰 경계를 그린다. 최소 범위의 정책을 설계하고 시험 환경에서 허용·차단 사례를 확인한 뒤 운영 로그를 관찰한다.
- **출력:** 변경 이유, 대상·기간·소유자, 롤백 절차, 실제 테스트 결과가 있는 정책 기록.

## 가상 실무 시나리오

**가상 시나리오:** 개발팀이 새 API와 데이터베이스 연결을 요청한다. 엔지니어는 API 워크로드만 데이터베이스 포트에 접근하도록 경로를 좁히고, 일반 사용자망에서는 접근이 거부되는지 시험한다. 배포 후 차단 로그에서 정상 트래픽 누락이 있는지 확인한다. 예외 규칙은 담당자와 만료일을 붙인다.

## 기반 지식

TCP/IP, 라우팅, DNS, TLS를 알아야 정책의 실제 적용 지점을 찾는다. 운영체제 소켓·프로세스 지식은 네트워크 접속의 주체를 확인하는 데 필요하다. 클라우드 보안 그룹과 Kubernetes 네트워크 정책 등 환경별 통제 차이도 이해해야 한다.

## 핵심 역량과 도구

패킷 캡처는 실제 통신을 확인하고, 정책 관리 도구는 규칙의 변경 이력을 남기며, 다이어그램은 업무 흐름과 차단 지점을 공유한다. 차단 로그의 부재가 안전의 증거는 아니다. [NIST SP 800-207](https://csrc.nist.gov/pubs/sp/800/207/final)의 자원 중심 접근 원칙을 참조한다.

## 신입 준비

‘네트워크 보안’, ‘방화벽 운영’, ‘클라우드 네트워크 보안’ 공고는 장비 운영과 설계 비율이 다르다. 작은 가상망에서 통신 행렬과 허용·차단 테스트를 설명할 수 있어야 한다. 특정 벤더 명령어 경험은 환경에 따라 유용하지만 보편적인 필수 요건은 아니다.

## 학습 순서

1. TCP/IP와 DNS를 익힌다 — 패킷 한 흐름을 설명하면 완료.
2. 서비스 간 통신 행렬을 만든다 — 주체·대상·목적을 기록하면 완료.
3. 최소 범위 규칙을 구현한다 — 허용·거부 사례를 실제 테스트하면 완료.
4. 변경 운영을 연습한다 — 롤백과 로그 검토 절차가 검증되면 완료.

## 실습 프로젝트

### 프로젝트 1: 세 구역 가상망 분리

- **목표·선수 지식·환경:** 사용자·API·DB 구역을 분리한다. IP·라우팅 기초와 로컬 가상망이 필요하다.
- **작업·검증:** 통신 행렬을 작성하고 정책 적용 전후에 각 경로를 시험한다.
- **산출물·완료 기준·포트폴리오:** 흐름도, 규칙, 허용·차단 증거를 제출한다. DB 직접 접근은 막고 API 경로는 유지되면 완료다.

### 프로젝트 2: 정책 변경과 롤백

- **목표·선수 지식·환경:** 잘못된 규칙으로 인한 장애를 안전하게 되돌린다. 방화벽 기초와 첫 프로젝트 환경이 필요하다.
- **작업·검증:** 의도적 차단 오류를 넣고 모니터링·롤백 절차를 실행한다.
- **산출물·완료 기준·포트폴리오:** 변경 요청, 시험 결과, 롤백 시간표를 남긴다. 정상 통신 복구가 확인되면 완료다.

## 관련 자격증

[GIAC GCIA](https://www.giac.org/certifications/certified-intrusion-analyst-gcia)는 트래픽 분석과 침입 탐지 지식을 점검하는 선택지다. 정책 설계·변경 관리 역량 전체를 대신하지 않으므로 통신 행렬과 허용·차단 검증을 먼저 익힌다.

## 관련 직무 차이

클라우드 보안 엔지니어는 계정·IAM·데이터 설정까지 클라우드 전체를 다룬다. 네트워크 보안 엔지니어는 통신 경로와 네트워크 통제의 설계·운영에 깊게 집중한다. 보안 아키텍트는 여러 통제 간의 구조적 결정을 책임진다.
