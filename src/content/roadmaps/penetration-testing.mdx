# 침투 테스트 로드맵

허가된 범위에서 웹의 신뢰 경계를 검증하고 재현·영향·수정 검증을 문서화하는 경로.

학습 속도는 배경지식과 실습 환경에 따라 달라진다. 각 단계의 완료 기준을 충족했는지 확인하고 다음 단계로 이동한다.

## 1단계 · 요청과 권한 경계 읽기

**선수 조건:** 사이버보안 기초

**학습 목표와 필수 개념:** DNS, HTTP, 쿠키, 세션, 인증과 인가를 학습한다. 반드시 소유하거나 명시적으로 허가받은 로컬·교육용 대상만 사용한다.

**권장 실습:** 두 계정이 있는 실습 앱에서 같은 요청의 헤더와 응답을 비교한다.

**검증 방법과 완료 기준:** 본인과 타인 객체의 접근 결과가 왜 다른지 요청 단위로 설명할 수 있다.

**다음 단계:** 위험 유형과 시험 설계로 이동한다.

## 2단계 · 테스트 가설 만들기

**선수 조건:** 1단계의 HTTP·권한 이해

**학습 목표와 필수 개념:** OWASP Top 10:2025와 API Top 10:2023을 위험 인식 자료로 읽고 자산별 가설을 만든다. 자동 스캔과 수동 검증의 차이를 배운다.

**권장 실습:** 로컬 앱의 입력·객체 ID·오류 응답에 대한 테스트 행렬을 작성한다.

**검증 방법과 완료 기준:** 정상 사례와 위반 사례가 모두 있고, 각 테스트에 기대 결과가 명시된다.

**다음 단계:** 증거와 재검증으로 이동한다.

## 3단계 · 안전한 재현과 보고

**선수 조건:** 2단계의 시험 행렬

**학습 목표와 필수 개념:** 최소한의 요청으로 문제를 재현하고 원인·영향·전제 조건·완화책을 분리한다. 스캔 범위와 테스트 데이터를 기록한다.

**권장 실습:** 의도적으로 취약한 교육용 앱에서 한 문제를 재현한 뒤 수정 버전에서 같은 요청을 다시 실행한다.

**검증 방법과 완료 기준:** 재현 절차, 원본 로그, 수정 후 결과를 타인이 따라 할 수 있다.

**다음 단계:** 개별 취약점 연구나 레드팀 전문화로 확장한다.

## 포트폴리오 프로젝트

### 프로젝트 1 · 인가 결함 재현 보고서

실습 앱의 두 계정과 객체 두 개로 권한 행렬을 만든다.

**완료 기준:** 허가 범위, 최소 재현 요청, 영향 받은 객체, 수정 후 회귀 테스트를 포함한다.

### 프로젝트 2 · 웹 테스트 플레이북

입력·세션·오류·설정에 대한 작은 테스트 묶음을 작성한다.

**완료 기준:** 스캐너 결과와 수동 검증을 구분하고 오탐 사례 하나를 설명한다.
