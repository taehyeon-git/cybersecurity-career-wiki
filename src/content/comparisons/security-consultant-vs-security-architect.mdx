# 보안 컨설턴트 vs 보안 아키텍트

범용 보안 엔지니어 대신 설계 책임이 분명한 아키텍트를 대비해 자문과 구현 설계의 경계를 살핀다.

이 비교는 NICE와 ECSF의 업무·역량 개념을 참고한 위키의 설명이다. 특정 프레임워크가 아래 채용 직함의 경계를 공식적으로 고정한다는 뜻은 아니다. 실제 공고에서는 업무가 겹칠 수 있다.

## 같은 기준으로 비교하기

### 주요 목적

- **보안 컨설턴트:** 고객·조직의 문제를 평가하고 실행 가능한 개선안을 제시한다.
- **보안 아키텍트:** 시스템과 조직의 보안 구조·신뢰 경계를 설계한다.

### 실제 업무

- **보안 컨설턴트:** 범위 협의, 인터뷰, 현황 평가, 권고안과 이행 계획.
- **보안 아키텍트:** 요구사항 분석, 통제 선택, 예외 설계와 구현 검토.

### 대표 산출물

- **보안 컨설턴트:** 진단 보고서, 위험 우선순위와 로드맵.
- **보안 아키텍트:** 참조 아키텍처, 데이터 흐름, 정책·설계 결정 기록.

### 필요 기반 지식

- **보안 컨설턴트:** 보안 프레임워크, 이해관계자 요구, 평가 방법.
- **보안 아키텍트:** 신원·네트워크·애플리케이션·클라우드의 상호작용.

### 도구와 기술

- **보안 컨설턴트:** 인터뷰·증거 분석·위험 등록부.
- **보안 아키텍트:** 위협 모델, 설계 다이어그램, 정책 검증 실습.

### 프로그래밍 활용

- **보안 컨설턴트:** 필수는 업무 범위에 따라 다르며 증거 분석 자동화에 유용하다.
- **보안 아키텍트:** 설계 검증용 구성 코드와 작은 PoC에 유용하다.

### 입문 준비와 프로젝트

- **보안 컨설턴트:** 실습 조직의 위험·통제 개선 보고서를 작성한다.
- **보안 아키텍트:** 같은 조직의 IAM·네트워크 경계 설계와 허용·거부 시험을 만든다.

## 공통점과 협업 지점

둘 다 기술과 업무 영향의 연결이 필요하다. 실제 채용명 Security Engineer는 AppSec, Cloud, IAM 등 여러 전문 업무를 가리킬 수 있어 한 역할로 단정하지 않는다.

## 진로 선택에 적용하기

여러 조직의 문제를 평가·설득하는 업무를 선호하면 컨설팅, 한 시스템의 보안 구조를 구체화하고 검증하는 업무를 선호하면 아키텍처를 탐색한다. 직함만 보지 말고 채용공고의 실제 업무, 산출물, 책임 범위를 확인한다.
