# 침투 테스터 vs 레드팀 운영자

범위를 정한 취약점 검증과 목표 중심의 공격 시뮬레이션은 수행 질문과 산출물이 다르다.

이 비교는 NICE와 ECSF의 업무·역량 개념을 참고한 위키의 설명이다. 특정 프레임워크가 아래 채용 직함의 경계를 공식적으로 고정한다는 뜻은 아니다. 실제 공고에서는 업무가 겹칠 수 있다.

## 같은 기준으로 비교하기

### 주요 목적

- **웹 침투 테스터:** 합의한 시스템의 취약점을 발견·재현하고 수정 우선순위를 제시한다.
- **레드팀 운영자:** 실제 공격자의 목표 달성 경로와 조직의 탐지·대응 능력을 시험한다.

### 실제 업무

- **웹 침투 테스터:** 범위·계정·테스트 시간에 맞춰 웹 기능과 권한 경계를 검증한다.
- **레드팀 운영자:** 공격 시나리오, 허용 기법, 안전 중단 조건을 정해 여러 단계를 수행한다.

### 대표 산출물

- **웹 침투 테스터:** 재현 절차, 영향, 원인과 수정 검증을 담은 취약점 보고서.
- **레드팀 운영자:** 목표 달성 경로, 방어 관측점, 탐지·대응 개선을 담은 훈련 보고서.

### 필요 기반 지식

- **웹 침투 테스터:** HTTP, 인증·인가, 취약점 분류, 안전한 테스트 설계.
- **레드팀 운영자:** 네트워크·신원·엔드포인트 경계와 공격자 행동·방어 운영의 연결.

### 도구와 기술

- **웹 침투 테스터:** 요청 기록 도구, 테스트 계정, 교육용 취약 앱과 재현 스크립트.
- **레드팀 운영자:** 허가된 시뮬레이션 도구, 활동 기록, ATT&CK 행동 매핑과 방어 로그.

### 프로그래밍 활용

- **웹 침투 테스터:** 재현 요청과 반복 검증을 작은 스크립트로 자동화한다.
- **레드팀 운영자:** 시나리오 준비·원격 작업·기록 정리에 스크립팅을 쓴다.

### 입문 준비와 프로젝트

- **웹 침투 테스터:** 로컬 앱의 권한 결함 하나를 최소 요청으로 재현하고 수정 후 시험한다.
- **레드팀 운영자:** 교육용 네트워크에서 목표·허용 범위·중단 조건을 적은 짧은 모의 훈련을 설계한다.

## 공통점과 협업 지점

둘 다 사전 승인된 범위와 안전 규칙이 필수이며, 발견한 현상을 증거로 설명해야 한다.

## 진로 선택에 적용하기

결함 자체의 원인과 수정에 집중하고 싶으면 침투 테스트를, 여러 방어 단계를 연결한 훈련을 설계하고 싶으면 레드팀 운영을 탐색한다. 직함만 보지 말고 채용공고의 실제 업무, 산출물, 책임 범위를 확인한다.
