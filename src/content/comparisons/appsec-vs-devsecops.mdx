# AppSec 엔지니어 vs DevSecOps 엔지니어

제품의 취약점 원인과 개발 의사결정에 집중하는 역할과 보안 검사의 지속 가능한 자동화에 집중하는 역할.

이 비교는 NICE와 ECSF의 업무·역량 개념을 참고한 위키의 설명이다. 특정 프레임워크가 아래 채용 직함의 경계를 공식적으로 고정한다는 뜻은 아니다. 실제 공고에서는 업무가 겹칠 수 있다.

## 같은 기준으로 비교하기

### 주요 목적

- **AppSec 엔지니어:** 애플리케이션의 설계·코드·동작상 위험을 줄인다.
- **DevSecOps 엔지니어:** 개발·배포 흐름에서 보안 활동이 반복 가능하고 검증 가능하게 수행되도록 한다.

### 실제 업무

- **AppSec 엔지니어:** 위협 모델링, 코드 리뷰, 권한 설계와 결함 수정 지원.
- **DevSecOps 엔지니어:** CI 권한, SAST·SCA·SBOM, 이미지와 배포 정책 운영.

### 대표 산출물

- **AppSec 엔지니어:** 취약점 분석, 안전한 설계 요구사항, 회귀 테스트.
- **DevSecOps 엔지니어:** 검사 파이프라인, 정책·예외 기록, 빌드 산출물의 추적 정보.

### 필요 기반 지식

- **AppSec 엔지니어:** 웹·API 구조, 언어별 결함, 인증·인가.
- **DevSecOps 엔지니어:** 버전 관리, 빌드 시스템, 자동화, 컨테이너·클라우드 운영.

### 도구와 기술

- **AppSec 엔지니어:** 코드·요청 분석, 위협 모델과 수동 검증.
- **DevSecOps 엔지니어:** CI 작업, 스캐너 연동, 아티팩트와 정책 검증.

### 프로그래밍 활용

- **AppSec 엔지니어:** 원인 코드 분석과 안전한 수정 예시를 만든다.
- **DevSecOps 엔지니어:** 파이프라인·검사 결과 처리와 배포 자동화를 작성한다.

### 입문 준비와 프로젝트

- **AppSec 엔지니어:** 교육용 API의 권한 행렬과 회귀 테스트를 만든다.
- **DevSecOps 엔지니어:** 실습 저장소에 최소 권한 CI, SAST, SCA와 SBOM을 붙인다.

## 공통점과 협업 지점

둘 다 SSDF의 안전한 개발을 돕고 검사 경고를 사람이 검토해야 한다. 조직에 따라 업무가 겹친다.

## 진로 선택에 적용하기

코드와 기능 설계의 원인 분석을 선호하면 AppSec, 개발 플랫폼과 반복 자동화 설계를 선호하면 DevSecOps가 더 가깝다. 직함만 보지 말고 채용공고의 실제 업무, 산출물, 책임 범위를 확인한다.
