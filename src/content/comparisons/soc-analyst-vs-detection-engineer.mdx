# SOC 분석가 vs 탐지 엔지니어

경보를 해석하는 업무와 탐지 논리·데이터 품질을 설계하고 검증하는 업무의 차이.

이 비교는 NICE와 ECSF의 업무·역량 개념을 참고한 위키의 설명이다. 특정 프레임워크가 아래 채용 직함의 경계를 공식적으로 고정한다는 뜻은 아니다. 실제 공고에서는 업무가 겹칠 수 있다.

## 같은 기준으로 비교하기

### 주요 목적

- **SOC 분석가:** 들어온 경보가 사건인지 판단한다.
- **탐지 엔지니어:** 유의미한 경보가 생성되도록 탐지 체계를 개선한다.

### 실제 업무

- **SOC 분석가:** 검색·문맥 확인·티켓 처리·에스컬레이션.
- **탐지 엔지니어:** 가설 정의·로그 요구사항·규칙 작성·오탐 시험.

### 대표 산출물

- **SOC 분석가:** 분류 근거와 사건 이관 기록.
- **탐지 엔지니어:** 규칙, 테스트 데이터, 적용 범위와 품질 지표.

### 필요 기반 지식

- **SOC 분석가:** 서비스 정상 패턴과 조사 절차.
- **탐지 엔지니어:** 로그 파이프라인, 공격자 행동, 쿼리와 테스트 설계.

### 도구와 기술

- **SOC 분석가:** SIEM 검색, 자산·신원 맥락 도구.
- **탐지 엔지니어:** 탐지 규칙 저장소, 테스트 하네스, ATT&CK 매핑.

### 프로그래밍 활용

- **SOC 분석가:** 사건 조회와 반복 수집을 자동화한다.
- **탐지 엔지니어:** 규칙·테스트·데이터 변환을 코드로 관리한다.

### 입문 준비와 프로젝트

- **SOC 분석가:** 샘플 경보의 정상·의심 분류 사유를 작성한다.
- **탐지 엔지니어:** 같은 샘플로 규칙을 만들고 오탐·미탐을 시험한다.

## 공통점과 협업 지점

SOC의 조사 피드백은 규칙 개선의 핵심 입력이고, 탐지 엔지니어의 결과는 SOC 작업량에 직접 영향을 준다.

## 진로 선택에 적용하기

실시간 사례 판단에 끌리면 SOC, 재사용 가능한 탐지 논리와 데이터 품질에 끌리면 탐지 엔지니어링을 탐색한다. 직함만 보지 말고 채용공고의 실제 업무, 산출물, 책임 범위를 확인한다.
