# 콘텐츠 작성 지침

## 독자가 확인할 수 있는 설명

1. 첫 단락에서 직무가 해결하는 문제와 대표 산출물을 설명합니다. 도구 목록만으로 직무를 정의하지 않습니다.
2. `실제 하는 일`, `필요한 지식`, `협업`, `입문 실습`, `인접 직무`, `근거와 한계`를 해당 페이지 성격에 맞게 구분합니다.
3. 표준에 적힌 명칭은 원문을 확인하고 버전을 적습니다. 위키가 합치거나 나눈 범주는 **편집상 분류**라고 표시합니다.
4. 자격증, 학위, 연차는 고정 필수 조건으로 단정하지 않습니다. 확인한 공고에서 요구했다면 회사·직무·확인일·표본 한계를 함께 적습니다.
5. 공격 기술은 합법적인 실습과 방어 이해에 필요한 수준으로 설명하고, 무단 접근이나 실제 대상 공격을 권하지 않습니다.

## 근거 등급

| 표현 | 작성 기준 |
| --- | --- |
| **공식 정의** | NIST NICE, ENISA ECSF, CISA, OWASP, MITRE 등 원문과 버전 확인 |
| **국내 공고 관찰** | 원 공고 URL, 회사·직무, 게시 또는 확인 시점, 읽을 수 있는 본문 범위 기록 |
| **편집 판단** | 복수 근거를 종합한 해석임을 명시하고 분류 결정 기록에 연결 |
| **미확인** | 공개 수치나 단정 문장으로 쓰지 않고 조사 필요 항목으로 남김 |

근거는 가능하면 1차 자료를 사용합니다. 2차 해설을 참고할 때는 원문과 서로 다른 주장인지 확인합니다. 출처는 `src/data/sources.json`의 ID로 재사용하고, 외부 링크가 바뀌면 확인일과 대체 URL을 갱신합니다. 출처가 신뢰할 만해도 특정 문장을 직접 뒷받침하는지 확인해야 합니다.

## 국내 채용공고 사용

`docs/research/korean-job-market.md`는 편의 표본이며 한국 채용시장 전체를 대표하지 않습니다. 공고 수를 시장 비율이나 순위로 바꾸지 않습니다. 회사별 중복과 접근 불가 공고를 구별하고, 채용 종료 후에는 과거 사례로 표시합니다. 검색 결과의 제목이나 요약만 보이는 경우 세부 업무를 재구성하지 않습니다. 급여·수요·성장률은 검증 가능한 자료가 없으면 쓰지 않습니다.

## 갱신과 저작권

표준·프레임워크의 버전, 공고 상태, 문서 링크가 바뀌기 쉽습니다. 새 버전이 나와도 기존 직무 매핑이 자동으로 바뀌는 것은 아니므로 변경 로그를 읽고 해당 페이지를 재검토합니다. 원문을 길게 복제하지 말고 독자적인 요약과 링크를 제공합니다. 이미지·표를 포함할 때는 [콘텐츠 라이선스](../CONTENT_LICENSE.md)의 외부 자료 규칙을 따릅니다.

게시 전에는 `npm run content:check`와 `npm run build`를 실행하고, 의미가 달라지는 수정은 검토일 `reviewedAt`과 검토 상태를 함께 갱신합니다.
