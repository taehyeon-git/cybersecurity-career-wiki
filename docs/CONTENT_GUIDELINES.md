# 콘텐츠 작성 지침

이 위키의 목적은 **보안 직무와 커리어를 이해하고 준비하는 데 필요한 정보**를 제공하는 것입니다. 직무 글은 기술 주제를 가르치는 문서가 아닙니다. 도구·기술은 그 직무가 실제 업무에서 왜 쓰는지와 어떤 결과물을 만드는지 설명할 때만 언급합니다. 독립 기술 강의, 직무 대결식 비교, 지식 지도용 노드 글을 새로 만들지 않습니다.

## 직무 페이지의 기본 질문

1. 이 역할의 책임 범위와 결정권은 어디까지인가?
2. 어느 조직에서 일하고 어떤 팀·고객·외부 업체와 협업하는가?
3. 실제 한 주의 업무는 어떤 요청, 판단, 실행, 인계로 이어지는가?
4. 다른 사람이 사용할 대표 산출물은 최소 두 가지 무엇인가?
5. 어떤 경력에서 진입할 수 있고, 신입은 무엇으로 업무 이해를 증명할 수 있는가?
6. 실제 공고에 적힌 필수·우대 조건은 무엇이며, 어느 회사·어느 시점의 정보인가?
7. 채용 직함이 넓거나 겹칠 때 지원자가 확인해야 할 업무 경계는 무엇인가?

글마다 책임, 흐름, 산출물, 협업, 진입·이직, 포트폴리오, 채용 근거와 미확인 사항을 담습니다. 합성 사례는 반드시 ‘가상’이라고 표시하고, 실제 기업의 내부 사건처럼 보이게 쓰지 않습니다. 임금·수요 전망·직무 순위는 출처 없이 추정하지 않습니다. 자격증과 학위, 경력 연수도 특정 공고의 요구를 업계 전체의 필수 조건으로 확대하지 않습니다.

## 근거의 사용

| 근거 | 사용할 수 있는 표현 | 피해야 할 표현 |
| --- | --- | --- |
| NCS 정보보호 SQF, NICE, ENISA | 업무 범주·역할 정의와 역량의 참고 자료 | 프레임워크 역할명이 국내 채용 직함과 정확히 같다는 단정 |
| 기업 공식 공고의 본문 | 해당 회사·시점의 담당업무와 확인된 요건 | 한 공고의 기술 목록을 모든 회사의 필수 요건으로 일반화 |
| 공식 공고의 목록·제목만 확인 | 해당 제목과 게시·확인 사실 | 본문을 보지 못했는데 세부 업무나 신입 가능 여부를 추정 |
| 과거에 종료된 공식 공고 | 과거의 직무 구성 사례 | 현재 모집 중이라는 안내 |
| 편집자의 종합 판단 | 출처를 연결하고 ‘이 위키의 분류’라고 명시 | 공식 분류의 새 항목처럼 제시 |

주장은 독자가 확인할 수 있는 공식 원문 가까이에 링크를 둡니다. 문서 맨 끝의 출처 목록만으로 모든 문장이 뒷받침된다고 가정하지 않습니다. `sourceIds`는 재사용하는 참고 자료 목록이고, 특정 채용 근거는 해당 문단에 회사·공고명·확인일·원문 링크와 함께 적습니다. 불확실한 내용은 삭제하거나 미확인이라고 명시합니다.

## 국내 채용공고 표본

[국내 채용공고 조사](research/korean-job-market.md)는 2026-10-09 확인한 **23개 공고의 편의 표본**입니다. 그중 **17개는 업무 본문을 확인**, **6개는 제목·기간 등만 또는 일부만 확인**했습니다. **토스 계열 12개**로 표본이 편중돼 있으며 공공·제조·중소 보안업체가 충분하지 않습니다. 이 숫자는 시장 점유율이나 채용 가능성 추정에 쓰지 않습니다. 한 공고에 여러 세부 포지션이 있어도 공고 수를 부풀리지 않습니다.

직무 글에서 이 표본의 `Pxx`를 인용할 때는 정확히 어떤 포지션의 업무를 확인했는지 명시합니다. 모집 상태가 바뀌면 과거 사례라고 표시합니다. 목록만 확인한 안랩·NAVER Cloud 공고는 상세 요건 근거가 아닙니다. 독립 공고를 찾지 못한 직무도 공식 SQF·NICE 등으로 업무의 존재를 설명할 수 있지만, ‘국내 채용이 활발하다’고 쓰지 않습니다.

## 범주와 인접 업무

직무는 [분류 결정 기록](research/classification-decisions.md)의 여섯 업무 범주 중 하나에 둡니다. 여러 분야를 겸하는 실제 채용은 한 범주에 억지로 맞추지 말고 본문에서 업무 결합을 설명합니다. 각 글에 필요한 경우 인접 역할과 책임의 경계를 두세 문장으로 적되, 별도의 직무 비교 페이지나 승패식 표는 만들지 않습니다. ‘Security Engineer’, ‘Security Researcher’, ‘보안 컨설턴트’ 같은 넓은 직함은 반드시 공고의 세부 업무를 확인합니다.

## 용어집·경로·갱신

용어집은 채용 공고와 직무 글을 읽는 데 필요한 짧은 정의를 제공합니다. 새 용어는 공식 출처 ID를 연결하고 직무와 관계없는 기술 설명을 확장하지 않습니다. 커리어 경로는 진입 순서의 **예시**로 작성하며, 특정 자격 취득이 취업을 보장한다고 쓰지 않습니다. 각 단계에는 수행할 일과 확인 가능한 결과물을 적습니다.

링크, 표준 버전, 공고 상태는 바뀝니다. 새 버전이 나오면 변경 로그와 실제 영향을 확인하고 관련 글의 `reviewedAt`, `reviewStatus`를 갱신합니다. 타인의 본문이나 표를 길게 복제하지 않고 자체 설명과 원문 링크를 제공합니다. 이미지·표의 권리는 [콘텐츠 라이선스](../CONTENT_LICENSE.md)를 따릅니다. 게시 전 `npm run content:check`와 `npm run build`를 실행하고, 중요한 독자 흐름은 실제 브라우저에서도 확인합니다.
