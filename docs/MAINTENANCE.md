# 유지보수 절차

이 위키의 공개 범위는 보안 직무 46개, 커리어 준비 경로 11개, 용어 69개입니다(2026-10-09 스냅샷). 분류는 NCS 정보보호 SQF를 참고한 여섯 실무 범주이며, 실제 조직의 직함·업무 분장은 달라질 수 있습니다. 개수나 분류를 바꾸면 [직무 인벤토리](research/role-inventory.md), [분류 결정](research/classification-decisions.md), 독자에게 보이는 설명을 함께 검토합니다.

## 정기 검토

| 주기 제안 | 확인할 내용 | 기록 위치 |
| --- | --- | --- |
| 매월 | 깨진 공식 링크, 목록·상세·검색 연결, 독자 제보 | 수정 PR 또는 이슈 |
| 분기마다 | 직무의 담당 범위·산출물·협업 상대·진입 경로, 용어의 직무 맥락, NICE/ECSF/NCS 출처 버전 | 관련 MDX·JSON, `src/data/sources.json`, `docs/research/` |
| 공고 인용 시마다 | 원 공고 접근 가능 여부, 조사 날짜, 제목만 확인했는지 본문까지 확인했는지, 마감·변경 상태 | [국내 공고 표본](research/korean-job-market.md), 관련 직무 문서 |

주기는 편집 제안입니다. 자동 최신성 보장은 없으며, 명백한 오류는 다음 검토일을 기다리지 않고 바로 고칩니다.

## 내용 수정 순서

1. 수정할 문장과 직접 연결된 공식 원문, 버전, 확인 날짜를 찾습니다. 국내 공고는 [표본 기록](research/korean-job-market.md)의 P번호를 확인합니다.
2. 공고의 **제목 확인**과 **본문 확인**을 구분합니다. 현재 표본은 23건의 편의 표본이며, 이 중 본문 확인 17건·상세 제한 6건이고 토스 계열 공고가 12건입니다. 이를 채용 규모나 직무별 수요 순위로 해석하지 않습니다.
3. 영향을 받는 직무, 경로, 용어, 출처 ID, 역방향 링크, 검색 별칭을 찾습니다. 실제 업무 기준이 바뀌면 [분류 결정](research/classification-decisions.md)도 갱신합니다.
4. 직무 페이지에는 책임 범위, 실제 업무 흐름, 산출물, 협업 관계, 진입·전환 방법과 채용 근거를 유지합니다. 기술 구현 튜토리얼이나 독립 기술 지식 페이지를 새로 만들지 않습니다.
5. MDX의 `reviewedAt`과 `reviewStatus`를 실제 검토 수준에 맞게 갱신합니다. 근거가 부족하거나 공개를 멈춰야 한다면 `publicationStatus`를 선택하고 이유를 PR에 기록합니다.
6. `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`를 실행합니다. 빌드된 `out/`에 대해 `npm run test:e2e`를 실행하고 공개 화면을 확인합니다. 실행하지 않은 검사는 통과로 보고하지 않습니다.

`publicationStatus: published`만 공개 목록·검색에 들어갑니다. `draft`, `needs-review`, `outdated`는 제외됩니다. `reviewStatus`는 편집 검토 상태이며 공개 여부를 직접 결정하지 않습니다. 근거가 사라진 내용을 억지로 유지하지 말고 문장 수정 또는 상태 변경을 검토합니다. 파일 삭제 시에는 다른 문서의 참조, 공개 URL, 외부 유입 링크를 먼저 확인합니다.

## 출처와 버전

`sources.json`의 `checkedAt`은 확인 날짜이고 `version`은 원문 버전입니다. 표준이 개정되어도 실제로 영향을 받는 직무·경로·용어만 수정합니다. 이전 공고의 당시 관찰을 새 공고 정보로 덮어쓰지 않고 조사 기록을 별도로 추가합니다. 일부 직함이 공식 프레임워크에 없다는 이유만으로 실제 회사의 직무를 지우거나, 하나의 공고를 여러 독립 채용 건수로 세지 않습니다.
