# 유지보수 절차

## 정기 검토

| 주기 제안 | 확인할 것 | 기록 위치 |
| --- | --- | --- |
| 매월 | 깨진 공식 링크, 검색 색인과 공개 문서 연결, 새 이슈 | 수정 PR 또는 이슈 |
| 분기마다 | NICE/ECSF 등 버전, 역할 분류 변경, 주요 토픽의 최신성 | `src/data/sources.json`, 관련 MDX, `docs/research/` |
| 공고 인용 시마다 | 원 공고의 접근 가능 여부, 마감·변경 상태, 제목과 본문 차이 | `docs/research/korean-job-market.md`, 관련 MDX |

주기는 편집 제안이며 자동화된 최신성 보장은 아닙니다. 고위험 변경이나 명백한 오류는 다음 정기 검토일까지 기다리지 말고 이슈와 PR로 처리합니다.

## 수정 순서

1. 해당 문장의 근거 원문과 버전·날짜를 확인합니다.
2. 영향 받는 출처 레코드, 문서, 역방향 연결과 검색 별칭을 찾습니다.
3. 사실 변경인지 편집상 분류 변경인지 구분합니다. 분류 변경은 `docs/research/classification-decisions.md`의 결정도 갱신합니다.
4. 관련 문서의 `reviewedAt`, 필요하면 `reviewStatus`와 `publicationStatus`를 갱신합니다. 출처가 사라졌고 대체 근거가 없다면 근거 없는 문장을 보류합니다.
5. `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`를 실행하고 변경 영향과 결과를 PR에 적습니다.

`published` 상태를 유지한 채 내용의 근거가 오래되었다면 갱신하거나 `outdated`로 바꿉니다. `outdated` 문서는 현재 구현에서 공개 목록과 검색 색인에서 제외됩니다. 별도 보존 정책 없이 파일을 삭제하지 마세요.

## 버전 추적

출처의 `checkedAt`은 링크와 내용 확인 날짜이고, `version`은 원문 버전입니다. 둘을 혼동하지 않습니다. 표준 버전이 바뀌면 변경 로그를 읽고 실제 영향을 받는 직무·토픽만 수정합니다. 국내 공고 자료는 조사 시점의 관찰로 남기되, 신규 공고가 생겼다고 예전 공고의 관찰을 덮어쓰지 않습니다.
