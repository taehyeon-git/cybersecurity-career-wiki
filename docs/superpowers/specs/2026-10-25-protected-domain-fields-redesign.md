# 보호 대상 중심 보안 분야 재구성

## 요청과 문제

사용자는 `보안 분야`를 전략·운영·진단 같은 업무 기능이 아닌 **시스템 보안, 웹 보안, OT 보안** 같은 보호 대상·기술 환경으로 찾고 싶다. 현행 9개 분야 안내는 직무군과 같은 축을 반복해 두 메뉴의 차이가 작다. 직무 페이지의 9개 기능별 분류는 기존 요구에 맞는 직무 탐색 축이므로 보존하되, 표시 이름을 `직무군`으로 구별한다.

## 정보 구조

15개 분야를 네 묶음으로 안내한다.

| 묶음 | 분야 ID |
| --- | --- |
| 인프라·접근 | system, network, cloud, endpoint, identity |
| 서비스·소프트웨어 | web, mobile, software-supply-chain, ai |
| 정보·신뢰 | data, cryptography |
| 산업·기기 | ot, iot-embedded, automotive, video-physical |

분야 글은 보호 대상, 실제 담당자의 일과 판단, 세부 환경, 산출물, 관련 직무, 입문·전환, 공고 확인점을 설명한다. 기술 구현·공격 지침은 싣지 않는다. 데이터 보안과 개인정보 보호의 법적 책임, 영상정보 시스템 보안과 물리 경비의 업무 경계, OT와 IoT, 차량과 일반 임베디드 기기의 경계를 분명히 한다. 이 15개는 공식 표준의 분야 수가 아니라 위키의 대상별 탐색 축이다.

## 데이터와 이동

분야 MDX는 기존 `category`를 제거하고 관련 `roleIds`를 명시한다. 한 직무가 여러 분야에 걸칠 수 있으며 범분야 직무를 특정 분야에 강제로 넣지 않는다. 분야 글에서 관련 직무로, 직무 글에서 실제 연결된 분야로 이동한다. 홈에는 분야 폴더 안에 15개 항목을 보여주고, 사이드바와 분야 목록은 네 묶음으로 정리한다. 검색과 사이트맵에는 새 15개 분야만 포함한다. 기존 9개 `/fields/{old}/` URL은 검색·사이트맵에 노출하지 않는 정적 이동 안내로 보존한다.

## 정확성과 검증

공식 NIST·OWASP·UNECE·개인정보보호위원회 자료는 **보호 대상과 업무 맥락**의 근거로, 국내 공고는 **그 자리의 역할** 근거로 사용한다. 어느 자료도 15개가 공식 분류라고 주장하는 근거로 쓰지 않는다. 스키마는 15개 분야 완전성, 관련 직무의 게시 상태, 중복 ID와 본문 링크를 검사한다. 단위 검사, 정적 빌드, 모바일·데스크톱 브라우저 경로, 배포 후 공개 URL을 확인한다.
