# 보안 분야 안내 폴더 설계

## 목적

처음 보는 독자가 보안 분야의 큰 갈래를 이해한 뒤 관심 있는 실제 직무로 이동하게 한다. 기존 위키의 폴더 탐색 감성을 유지하고 기술 강의, 직무 우열 비교, 근거 없는 채용·급여 일반화를 넣지 않는다.

## 접근

- 기존 직무 폴더에 긴 소개를 넣기: 구현은 단순하지만 60개 직무 목록을 읽기 어렵게 만든다.
- 별도의 `보안 분야` 폴더에 분야 안내 9편을 두기: 분야와 직무를 구분해 읽을 수 있고 현재 60개 직무를 빠짐없이 연결할 수 있다. **채택.**
- 세부 주제마다 수십 개 문서를 만들기: 내용 중복과 근거 부족을 키운다. 세부 분야는 각 분야 안내 글 안에서 설명한다.

## 정보 구조

홈·상단 탐색·사이드바에 `/fields/`를 직무 폴더 앞에 배치한다. `/fields/`는 9개 분야를 쉬운 정의와 대표 업무로 보여 주는 색인이고 `/fields/{category}/`는 한 분야의 자세한 안내다. 9개 분야는 현재 `roleCategories`와 일치하므로 60개 직무 각각이 한 분야 글에서 반드시 연결된다. 여러 분야에 걸친 일은 본문에서 서로 연결한다.

각 상세 문서는 쉬운 정의, 실제 업무 흐름, 결정과 산출물, 세부 분야, 협업 상대, 입문·전환, 공고 읽기, 관련 직무, 근거와 한계를 설명한다. 특정 기술의 사용 절차는 싣지 않는다. 색인에는 금융 FDS, 일반 물리 경비, 안전·품질, 일반 IT·SRE 등 인접 업무와 위키 범위의 차이를 간결하게 설명한다.

## 사실 기준

NCS 정보보호 SQF의 5개 하위산업분야·15개 직무를 기준 자료로 쓰되 위키의 9개 폴더를 공식 체계로 표현하지 않는다. NIST NICE의 Work Role과 기업 채용 직함, ENISA ECSF의 대표 역할 프로필과 보안 산업 전체 분야 수를 혼동하지 않는다. 실무 예시는 직무 안내이며 회사별 채용 요건으로 단정하지 않는다. 분야마다 공식 출처와 검토일을 제공한다.

## 검증

콘텐츠 스키마가 9개 분야와 60개 직무 연결을 보장한다. 정적 빌드·내부 링크·검색 색인·사이트맵이 9개 상세 경로를 포함한다. 브라우저에서 홈→분야→직무, 모바일 사이드바, 전역 검색과 320px·데스크톱 레이아웃을 확인한다.
