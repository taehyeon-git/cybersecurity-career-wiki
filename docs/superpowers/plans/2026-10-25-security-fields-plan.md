# 보안 분야 폴더 구현 계획

## 파일과 책임

- `src/content/fields/*.mdx`: 9개 분야의 한국어 설명과 출처.
- `src/lib/content.ts`, `src/lib/validation.ts`: field 스키마, 게시물 로딩, 출처·직무·분야 링크 검증.
- `src/app/fields/page.tsx`, `src/app/fields/[slug]/page.tsx`: 폴더 색인과 정적 상세 문서.
- `src/lib/site-data.ts`, 홈·사이드바·헤더·시작 안내·직무 상세: 분야 안내 연결.
- 검색·사이트맵·정적 빌드 검증: 새 문서를 공개 탐색 경로에 포함.
- `tests/`: 분류 완전성과 실제 독자 경로 검증.

## 단계

1. 분야 MDX 모델과 검증을 추가한다. 필수 값은 slug, 제목, 쉬운 요약, category, 공식 출처, 검토일이다. 연결 직무 ID는 게시된 직무의 category에서 자동 산출해 누락을 막는다. 각 현재 분야가 게시 문서 하나를 갖고 모든 60개 직무가 자기 분야에 연결되는지 검사한다.
2. 초심자용 분야 문서 9편을 작성한다. 각 글은 목적·실제 하루·산출물·세부 분야·협업·진입·공고 읽기·관련 직무·근거 한계를 포함한다.
3. `/fields/`와 `/fields/[slug]/`를 정적으로 만들고 기존 `DocumentShell`을 재사용한다. 홈의 별도 폴더, 사이드바, 상단·하단 탐색, 시작 안내, 직무 상세의 역방향 링크를 잇는다.
4. 전역 검색, 사이트맵, 정적 산출물 검사를 확장한다. 색인에는 분야 9건이 들어가고 삭제된 기술 지식·비교 경로는 다시 만들지 않는다.
5. 콘텐츠 검사, 타입, 린트, 단위·브라우저 테스트, 정적 빌드를 실행한다. 모바일·데스크톱 화면을 점검한 뒤 독립 검토를 받고 GitHub Pages에 배포한다.

## 중점 검증

- 존재하지 않는 분야·직무 링크가 콘텐츠 검사에서 실패하는가.
- 분야 색인의 9개 문서가 모두 열리고 각 글의 실제 직무 링크가 작동하는가.
- 전역 검색이 분야 문서를 찾고 기존 직무·경로·용어도 유지하는가.
- 모바일 폴더와 상세 문서 목차가 조작 가능하고 가로 넘침이 없는가.
- 정적 export와 공개 사이트맵에 분야 9개가 모두 포함되는가.
